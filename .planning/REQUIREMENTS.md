# Requirements: Article Group Concierge (owner-ready quality)

**Defined:** 2026-11-20 (seeded from `eval/PLAN.md`)
**Core Value:** Never misrepresent AG's work. A wrong claim about a client engagement is worse than a weak answer.

## v1 Requirements

### Eval (measurement)

- [x] **EVAL-01**: The grader compares numbers after normalising them ("8M+" matches "over 8 million"), so `metrics_not_in_context` flags only true mismatches
- [x] **EVAL-02**: The report counts unsupported claims by kind (goal stated as a result, capability not shown in the portfolio, generated/invented tags, other) per response and in total
- [x] **EVAL-03**: The grader sees only what the app saw (query plus retrieved context), not the persona profile
- [x] **EVAL-04**: The Strategy Lead / CTA expectation is driven by one shared config (which query types should offer a Strategy Lead), used by both the app prompt and the rubric, and the rubric's component-count rule matches the prompt
- [x] **EVAL-05**: The eval can run N times on the same query set and report each metric's mean and spread (min–max or SD)
- [x] **EVAL-06**: An optional second grader from another provider (via OpenRouter) grades a ~15-response sample, and the report shows an agreement score with the Opus grader
- [x] **EVAL-07**: The report states the run's provider route and model IDs, and compares each metric to the frozen baseline (`2026-11-20T15-12-31`)

### Content and data

- [x] **DATA-01**: All 50 articles are chunked and embedded (additive only; no deletes), and `hybrid_search` can return them
- [x] **DATA-02**: A diff of articlegroup.com/work against the index lists every missing piece of work, and each one (including the Simons Foundation education division and the Salesforce partner-ecosystem work) is ingested after user confirmation
- [x] **DATA-03**: The capability/industry taxonomy reflects each case study accurately (not 39/43 "technology"). Data changes are applied only after user approval
- [x] **DATA-04**: The slug maps in `detectQueryIntent` reference only slugs that exist in the DB
- [x] **DATA-05**: Every case-study video has been checked against its case study. Mismatches (e.g. Google cross-product → `Google_Recruiting_-_Technical_Judgment.mp4`) are fixed or removed, with the audit result recorded

### Retrieval

- [x] **RETR-01**: `hybrid_search_v2` exists alongside `hybrid_search` and does keyword search over the whole corpus with OR semantics, title/client weighting and reciprocal rank fusion
- [x] **RETR-02**: Intent detection matches whole words only (no "ai" inside "maintain"), or the filter is removed if it doesn't help recall
- [x] **RETR-03**: Retrieval returns the top-k without the 0.15 combined-score cutoff
- [x] **RETR-04**: A catalogue of all case studies is in the system prompt as a cached prefix, and cache hits are verified through OpenRouter usage fields
- [x] **RETR-05**: When fewer than 4 relevant case studies exist, the response presents what exists without padding or misrepresentation
- [x] **RETR-06**: Expected case-study recall is ≥ 90% (baseline 75%). A reranker or query rewriting is added only if this isn't met otherwise, chosen after checking current docs

### Generation

- [ ] **GEN-01** (Partial: goal_as_result 2, claims 6/50): The prompt states honesty rules: no goals stated as results, no capabilities the portfolio doesn't show, and plain acknowledgement when AG hasn't done a kind of work (config flag), followed by the closest real work
- [x] **GEN-02**: Invention-bait queries (presupposing work AG hasn't done) are answered without presupposing the work
- [x] **GEN-03**: Teaser `capabilities`/`industries` are filled server-side from DB links, never generated by the model
- [ ] **GEN-04** (Partial: voice 4.36 vs 4.5): The narrative is 2–4 sentences, adds something beyond the teasers, and uses AG's "we" voice (voice score ≥ 4.5)
- [x] **GEN-05**: Video components are used when the query is about video and the case study has a verified video
- [ ] **GEN-06** (Partial: fallback 20/21): The Strategy Lead conversation is offered on fallback, pricing and timeline queries per the shared config
- [x] **GEN-07**: If unsupported claims remain at ≥ 5/50 after GEN-01..06, a verifier pass is evaluated against its latency cost

### Speed

- [ ] **PERF-01**: Retrieved teasers are on screen in about 1.5 s
- [ ] **PERF-02**: The generated hero streams in and starts showing within about 3–4 s, using the streaming path
- [x] **PERF-03**: A startup/health check confirms the provider route (OpenRouter) and the remaining credit, and fails clearly when either is wrong

### Proof

- [ ] **PROOF-01** (Not met: counted runs not executed, budget; one original-50 run misses voice, unsupported claims, goal_as_result): An expanded query set is run three consecutive times, and every ready-bar check holds on all three
- [x] **PROOF-02**: A one-page before/after compares the baseline with the final runs metric by metric
- [ ] **PROOF-03** (Partial: five verified under the user-approved claims rule; 4 of 5 pass the original stability rule; no multi-part or pricing query): Five demo queries are chosen and verified to produce accurate, strong responses for the owner demo

### Output guard and claim tracing (Phase 06.1)

- [x] **GUARD-01**: A deterministic post-generation guard (no model call) removes retrieval-wording leaks, rewrites count/exhaustiveness claims to non-exhaustive forms and rewrites first-person "I" to "we" in every user-visible text field, on both the JSON and the streaming route
- [x] **GUARD-02**: The guard is replayed free ($0) over every saved answer (eval/results and the 06-DEMO rounds); every leak and count change and a sample of first-person changes are reviewed, with 0 false positives left
- [x] **TRACE-01**: Every unsupported claim in the saved harness-v4 runs is traced to the text that produced it (hero, StrategyCard, teaser summary or narrative), and the grader-view vs user-view hero gap is measured
- [x] **TRACE-02** (Partial: order_of_work fixed deterministically; goal_as_result, designed-and-produced, channel inference documented as not fixable deterministically): Source fixes found by the trace are implemented as deterministic code (no new prompt rules) or documented as not fixable deterministically
- [x] **CONFIRM-01**: One user-approved full original-50 run (Sonnet 5.5 generation, Opus 5.5 judge) reports deltas against 2026-11-25T14-30-56 and the ready bars; spend is logged

### Fast hero restatement (Phase 7)

- [x] **HERO-01**: A deterministic restatement detector (no model call) flags a HeroBlock challengeSummary that restates the user's query; replayed free over every saved run it gives the before rate (>= 45/50 user-seen heroes flagged in 2026-11-26T05-24-15) and every eval report shows `hero_restates`
- [x] **HERO-02**: The fast-hero-pass instruction v2 no longer asks the hero to restate the query: the challengeSummary names the problem behind the question in one sentence of at most 25 words, makes no claim about our work and keeps user-attributed work out of the hero; v1 stays selectable with HERO_PASS_PROMPT_VERSION=1; main system prompt and rubric unchanged
- [x] **HERO-03**: A deterministic guard fallback drops restating sentences from the HeroBlock challengeSummary (removing the field when nothing is left) on both chat routes, behind HERO_RESTATEMENT_GUARD_ENABLED and OUTPUT_GUARD_ENABLED; a free replay over saved answers is reviewed with 0 false positives left
- [x] **HERO-04**: A user-approved 10-query trial and then a user-approved full original-50 run (Sonnet 5.5 generation, Opus 5.5 judge) report hero_restates, voice, unsupported-claim responses, goal_as_result, hero-sourced claims, hero gap and hero latency against 2026-11-20T15-12-31 and 2026-11-26T05-24-15; spend is logged

## v2 Requirements

- **V2-01**: Automated nightly eval with regression alerts
- **V2-02**: Populate `document_metrics` / `visual_assets` from source PDFs for richer MetricGrid/VisualAsset content

## Out of Scope

| Feature | Reason |
|---------|--------|
| Changing the generation model (Sonnet 5.5) or the judge model (Opus 5.5) | Fixed by the user |
| Replacing `hybrid_search` in place | Shared Supabase project; it would change the live site immediately |
| Reranker / query rewriting by default | Only if recall < 90% after the RETR-01..05 fixes (RETR-06) |
| Verifier pass by default | Only if unsupported claims ≥ 5/50 after the prompt fixes (GEN-07); latency cost |
| New UI features unrelated to quality/speed | Not needed for the owner demo |
