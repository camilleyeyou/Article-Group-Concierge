## Spacing Scale

Declared values (multiples of 4). These are the Tailwind steps already used by the components:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, skeleton line gaps (`gap-1`) |
| sm | 8px | Pulse-dot gap, skeleton line gaps (`gap-2`, `mb-2`) |
| md | 16px | Default element spacing, error banner padding (`p-4`) |
| lg | 24px | Card padding (`px-6`), grid gap (`gap-6`) |
| xl | 32px | Block-to-block gap (`mb-8`), loading card padding (`p-8`) |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

Exceptions: skeleton bar heights mirror the rendered line boxes they stand in for: `HeroBlock` h1 uses `text-2xl/3xl/4xl` with `leading-tight`, i.e. about 30px / 37.5px / 45px line height at mobile / md / lg; label about 16px; summary about 20-26px. Use `h-3` (12px) for the label bar, `h-7 md:h-9 lg:h-11` (28/36/44px) for title bars, and `h-4` (16px) for summary bars, then verify each against the rendered hero. Thumbnail placeholder keeps the existing `aspect-[4/3]` ratio. Touch target for "Try again" / "Dismiss" unchanged.

## Interaction and State Contract

Focal point: the hero (skeleton, then streamed `HeroBlock`) is the primary visual anchor of the response; the teaser deck is secondary. The loading status line is tertiary and must not out-weigh either.

### Request timeline (what the prospect sees)

| Stage | Trigger | UI |
|-------|---------|----|
| 0. Submitted | request start | Existing loading card appears immediately: spinner square, status line, pulse dots. Input and submit disabled (existing `isLoading`). |
| 1. Instant teasers (D-501/502, target ~1.5 s) | first teaser event | Reserved hero skeleton (see below) above N instant teaser cards (N from `concierge-config.ts`, default 3) in their final grid slots. Loading card shrinks to a one-line status beneath the deck. |
| 2. Hero streaming (D-505/506, target ~3-4 s) | first hero text | Skeleton replaced in place by real `HeroBlock`; subtitle, title, challengeSummary text type in progressively as tokens arrive. Hero keeps the reserved height: no jump. |
| 3. Components complete | each component complete | StrategyCard, VideoPlayer, MetricGrid appear whole with `animate-fade-in` (no partial rendering). Teaser summaries swap in place (DB line replaced by the model's tailored line). |
| 4. Reconcile (D-501) | final layout event | Keep teasers the model also chose, reorder to model's order, add missing, remove unchosen. Narrative types in; follow-up chips appear last. Loading status removed. |
| 5. Error mid-stream (D-507) | stream fails after content on screen | Keep everything rendered. Existing error banner appears below the deck with the classified message and "Try again". Do not clear the partial deck. Stop typing animation, remove skeletons and loading status. |
| 6. Error before any content | failure before first event | Existing behaviour: error banner, no deck. |

### Suppression state (D-504)
For no-match, fallback and invention-bait queries (deterministic pre-model signal), stages 1 is skipped: show only the existing loading card (plus hero skeleton, since the hero is still coming) with no teaser cards, until the streamed hero arrives. Never show teaser cards "adjacent" to such a query. If the model later returns teasers on its own, they appear at stage 3 as normal complete components.

### Instant teaser card (D-502, D-503)
- Same `CaseStudyTeaser` component and classes. Props from DB only: title, clientName, DB-linked capability and industry tags, thumbnailUrl if available, `deliverables` verbatim as `summary`.
- No deliverables line: render the card without the summary paragraph (do not reserve blank text and do not substitute placeholder text). The summary region fills when the model's summary arrives; use the existing dark header, which grows naturally. Accept this small shift only for that card.
- No "instant"/"preview"/"match" badge, no relevance score, no ranking language. Cards are visually identical to final cards so nothing looks provisional or like a claim.
- Not interactive-disabled: `slug` link remains live (View project works at once).
- Removal by reconcile: fade out over 150ms (`opacity` only) then collapse with the grid reflow; do not animate height.

### Reserved hero skeleton (D-503)
- Container matches `HeroBlock`: `rounded-xl`, `px-6 py-10 md:py-14`. HeroBlock supports `dark`, `light` and `gradient`; the final variant is not known before the hero arrives, so the skeleton always uses the dark treatment (`#1A1818` base, `bg-white/10` bars). `gradient` is dark-based (`from-[#1A1818] to-[#333]`), so a swap to `dark` or `gradient` is a no-flash change (gradient adds only a subtle tone shift). Swap to `light` is a colour-only change at identical size. Bars: label `h-3 w-24`, two title bars (`h-7 md:h-9 lg:h-11`) at `w-3/4` and `w-1/2`, two summary bars `h-4` at `w-full max-w-2xl` and `w-2/3`.
- Fixed min-height equal to the rendered hero at the same breakpoint (`min-h-[220px] md:min-h-[260px]` as a starting point). The executor must verify both the min-height AND the title/summary bar heights against the rendered HeroBlock at each breakpoint and adjust so the CLS contribution of hero arrival is 0. If the final `backgroundVariant` is `light`, the swap is a colour change only; no size change.
- `animate-pulse` on bars only, not on the container.

### Streaming text
- Hero and narrative text render as tokens arrive, appended in the same element, no per-character animation library, no cursor glyph. Optional: 2px-wide caret is NOT used.
- Announce for assistive tech: the message container is `aria-live="polite"` with `aria-busy="true"` while streaming and `false` on completion. Do not make each token an announcement; announce the hero once complete (polite region updated at hero-done) and the narrative once complete.
- Auto-scroll: do not force-scroll while streaming. Scroll to the new response container once at stage 1 (existing `messagesEndRef` behaviour), then leave the viewport alone so the reader is never yanked.
- Prevent double submit: existing disabled state stays until stage 4 completes or errors.

### Motion
- New blocks: existing `.animate-fade-in` (opacity only, `--duration-base`). No translate on streamed or swapped content (avoids layout shift).
- Teaser summary swap: cross-fade 150ms opacity, same box.
- `prefers-reduced-motion: reduce`: disable `animate-pulse` on skeletons and dots (static grey/static dots), disable fade (instant show), keep progressive text (it is content, not decoration). `design-system.css` (lines ~531-548) already has a global `@media (prefers-reduced-motion: reduce)` block that does not cover Tailwind `animate-pulse` / `animate-spin`. Extend that existing block with `.animate-pulse, .animate-spin { animation: none; }`; do not add a second block.

### Layout shift budget
- Target CLS contribution from this phase's states: < 0.05 total. Allowed shifts: card removal at reconcile, summary appearing on a card with no DB deliverables, follow-up chips appearing at the end (below the fold of the deck).

## Copywriting Contract

Rule: any text shown before generation completes comes from the catalogue verbatim or is neutral status text. No claim about AG, a client, a result or a capability may be written by the UI. No sentence implying a match or confirmation ("Here are projects that match...", "We found...") before the model has framed the answer.

| Element | Copy |
|---------|------|
| Primary CTA (submit) | unchanged: existing submit button label |
| Loading status, stage 0 (replaces "Finding relevant case studies...", which presupposes a match) | "Looking through Article Group's work..." |
| Loading status, stage 1-3 (shown as one line below the deck) | "Writing your answer..." |
| Instant teaser summary | DB `deliverables` line verbatim; if absent, no summary |
| Suppressed-query loading (D-504) | "Looking through Article Group's work..." (same as stage 0, held until hero arrives) |
| Empty state heading | not applicable (this phase adds no empty state; existing landing state unchanged) |
| Empty state body | not applicable |
| Error state, stream failed after content (D-507) | Existing `classifyError` message (defined server-side in `src/app/api/chat/route.ts`), unchanged, shown in the existing banner below the kept deck. The stream path must surface the classified message and `retryable` flag to the client, e.g. as a final `error` stream event, since the client cannot classify errors itself. Banner leads with nothing new; the "Try again" button label stays "Try again" and re-submits the failed query (existing `handleRetry`). |
| Error state, failed before content | Existing `classifyError` message and banner, unchanged |
| Destructive confirmation | not applicable (no destructive actions in this phase; "Dismiss" on the banner is non-destructive) |
| Health check (PERF-03) | Server-side/admin JSON only. No end-user UI, no credit figures on any public surface (D-515). Status strings `ok` / `warn` / `fail` with a plain-language reason, in the `/api/health` JSON. |

## Accessibility Checks

- Skeleton and loading regions: `aria-hidden="true"` on decorative bars; the single status line carries the text and sits in the polite live region.
- Error banner keeps `role="alert"` (existing). It must not steal focus from the partial deck.
- Contrast: skeleton bars are decorative (exempt). Status text `#6B6B6B` on white = 5.3:1, which passes AA at the 16px size it renders at.
- Teaser links remain keyboard-focusable during streaming; reconcile must not reorder the DOM under a focused card without keeping focus on the same element (use stable `key` = case-study slug/id).

## Checker Recommendations for the Planner (non-blocking)

- **Hero variant flash:** `HeroBlock` defaults `backgroundVariant` to `'light'`, but the skeleton is always dark. Check which variant the model usually emits. If it is `light` or omitted, use a neutral skeleton or take the variant from an early stream event so the swap does not flash.
- **Summary bar height:** `h-4` (16px) is shorter than the summary line it stands in for (`text-sm leading-relaxed` is about 22.75px, `md:text-base` about 26px). Use `h-5` or add gaps so the stacked bars match the paragraph height. This is covered by the existing verify-and-adjust instruction.
- **Retry button:** show "Try again" only when the final `error` event has `retryable: true`. That matches the current `page.tsx` behaviour, and some errors (for example embeddings quota exceeded) are not retryable.
- **Mid-stream `error` event:** include `contactCTA` if the client uses it, and keep `failedQuery` handling intact for `handleRetry`.
