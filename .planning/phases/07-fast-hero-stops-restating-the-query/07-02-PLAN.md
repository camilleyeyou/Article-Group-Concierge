<objective>
Replace the fast-hero-pass instruction with a v2 that frames the problem behind the question instead of restating it, keep v1 one env var away, and make the cache key follow the version.

Purpose: HERO-02. The current instruction (src/lib/concierge-config.ts `heroPassInstruction`) literally asks for restatement: "states the user's challenge or opportunity in their own terms" and allows "You're asking about...". That is the likely cause of 49/50 restating heroes (06.1-EVAL-DELTA). This is a removal of a bad instruction plus a format constraint, not a new honesty rule: Phase 6 showed stacked prompt rules made voice and claims worse, so v2 keeps all v1 honesty clauses verbatim and changes nothing else. The hero stays claim-free about AG ("lead with insight", not with AG's past work): putting AG's work into a hero written before the rest of the answer would reopen hero-sourced claims, which are 0 today and Core Value says a wrong claim is worse than a weak answer.
Output: v2 instruction + switch, cache key field, tests. No paid calls (the effect is measured in 07-04/07-05).
</objective>

The v2 instruction text (use exactly; it begins with two newlines like v1):
```
\n\nFAST OPENING PASS: output ONLY the opening ```json block with a layout array that holds just the HeroBlock, then stop. Do not write any other component, the narrative or the follow-up questions; another pass writes them.
The user has just written their question, so the HeroBlock must not repeat it back. It names the problem behind the question the way a senior strategist would frame it, as a headline about THEM. It is written before the rest of the answer, so it makes no claim about us at all, and it must hold under the HONESTY RULES:
- challengeSummary: one sentence of at most 25 words that names the tension, stakes or decision underneath the question. Do not restate or paraphrase the question, and do not address the user as "you" ("You're asking...", "You want...", "You need..."). Example for "We're a fintech startup looking to rebrand": "Looking credible enough to hold people's money while still feeling new."
- Title and subtitle name the topic or the user's situation. They never describe our experience, clients, industries, seniority, scale or results (no "X work", "X experience", "our work with", "senior-level partnership", "Fortune 100"). Bad: "Senior-level work for global retailers". Good: "Choosing comparable work for a global retailer".
- Anything the user says or assumes about us ("X experience", "the campaign you did") is their question, not a fact. Keep it out of the HeroBlock entirely: no client, brand or project name the user attributes to us, in any field.
- Do not add facts the user did not give (company size or status, deadlines, audience traits, budget).
```
