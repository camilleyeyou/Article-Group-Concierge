<objective>
Chunk and embed AG's articles so retrieval can return them (DATA-01), without duplicating the existing 50 `documents` rows
(D-14) and without exposing company-info or LinkedIn text to the live `hybrid_search` (D-15, D-16, D-18).

Purpose: 50 articles have zero chunks, so AG's thinking is never retrieved. Production shares this Supabase project, so every
inserted chunk is live immediately. The live `hybrid_search` takes the top `match_count*3` semantic hits then returns only
`match_count` (= 20) rows; several hundred article chunks could push case studies out of that window and lower recall. So this
plan simulates the impact first and the user decides before anything is inserted.

Output: `scripts/embed-articles.ts`, `data/article-classes.json`, `data/held-article-chunks.json`, an impact report, and
article chunks in `content_chunks` for the 44 non-held docs (if the user approves).

Cost: text-embedding-3-small via OpenRouter, ~$0.02 per 1M tokens. 50 articles + 50 query embeddings is well under $0.05.
</objective>

